TL;DR

DJ Playprint is an evidence-backed search system for a practical question: what records does a DJ actually play? Two working profile artifacts and two corpus receipts now test four unlike source conditions. Batu supplies strong identifiers. Four Tet supplies broad but weak identity evidence. Seth Troxler exposes B2B attribution and dirty text. Carl Craig exposes aliases and version history. On-demand arbitrary-DJ search remains open.

The Recording-Finder Problem

A copied tracklist can tell me what somebody typed. It cannot tell me whether the record exists under that spelling, which version played, whether the link still works, or where the artist actually sells it.

DJ Playprint starts with a DJ name and follows the evidence until it reaches a recording. Every useful result needs a chain that can survive inspection.

  1. 01DJ identity
  2. 02Set evidence
  3. 03Timestamp
  4. 04Recording identity
  5. 05Version
  6. 06Listen or buy

Copying the string is the easy part. Proving what it points to is the product.

The Sources Are Unequal

The research spikes tested Batu, Four Tet, Seth Troxler, and Carl Craig across radio archives, community databases, and music catalogs. The result was not one universal scraper. It was a source hierarchy.

Authoritative structured lane

NTS Radio

Public endpoints preserve source-owned episode and track data. Batu is identifier-rich; Four Tet shows how sparse the same lane can be.

Supported discovery lanes

Mixcloud, BBC, independent radio

Official APIs or parseable public pages can extend coverage, but every adapter needs its own terms and attribution review.

Community leads

MixesDB and 1001Tracklists

Useful for discovery and corroboration. They do not become authoritative simply because the tracklist looks complete.

Excluded from automation

Resident Advisor

Technically extractable, but outside the production ingestion boundary under the current terms and robots policy.

Rinse remains useful as a recording node, but the sampled episode pages did not carry populated tracklists. Audio recognition may eventually fill some gaps. It stays outside the first product because it changes the cost, rights, and confidence model all at once.

A Link Is Not a Match

NTS supplied 84 unique Deezer catalog IDs in the Batu corpus. A current API audit found 59 readable records and 25 catalog records that were not readable from this region. Eighty-two API ISRCs matched the NTS ISRC. The 50-record pilot admits a track only when the destination is readable now and the ISRC matches exactly.

Set evidence→Exact recording→Release evidence→Checked destination

Ploy’s “Ramos” is the first complete cross-archive receipt: set evidence, exact recording, official listening page, Discogs release evidence, and direct Bandcamp purchase. Other retailer buttons remain labeled searches until the release and version are verified. Three literal unknown-ID rows remain open. I did not guess them away.

From Batu to Any DJ

Two profile runs prove that the pipeline can operate under unlike source conditions. Two additional corpus receipts expose the next hard cases before the interface claims to solve them. Seth forces collaborative attribution and dirty-line handling. Carl forces alias and version resolution across three decades. The general product should search on demand rather than copy the entire DJ internet into one brittle database. A cache hit can return existing evidence immediately. A cache miss can resolve identity, discover supported set sources, run the appropriate adapters, normalize tracks, and preserve every source URL and checked date.

What Is Proven and What Is Not

Proven now

  • Evidence and provenance model
  • Batu and Four Tet profile-scoped extraction
  • Seth and Carl corpus-level stress tests
  • Exact-identifier and strict text-match gates
  • Searchable desktop and mobile prototype
  • Automated integrity and browser checks

Still open

  • Arbitrary DJ identity resolution
  • Production source adapters
  • Commercial ingestion permissions
  • Release-level purchase resolution at scale
  • Dedicated Seth and Carl artifact runs
  • Coverage testing beyond four DJs

The repository stays private while the source and data-rights boundary is reviewed. The next build turns the profile runner into a search API and tests more DJs who do not have Batu’s unusually strong NTS record.
