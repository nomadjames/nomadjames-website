Accessibility Audit Suite

WCAG 2.1 AA/AAAContrast AnalysisVoiceOver TestingPDF RemediationSocial Media AuditCognitive Accessibility
TL;DR

I ran a multi-method accessibility audit across music tech, news, social media, and academic documents. The work covered WCAG (the Web Content Accessibility Guidelines), VoiceOver testing, contrast analysis, PDF remediation, and cognitive accessibility. Among the findings: link text at a 2.4:1 contrast ratio against a 4.5:1 minimum, and Instagram alt text that was all auto-generated.

My Approach

The work was five assignments, each using a different method on different material: social media content, commercial websites, an interactive learning platform, a PDF document, and direct assistive technology testing.

  • Social media content audit: a university Instagram feed
  • Contrast ratio and color blindness analysis: three music tech websites via WebAIM Contrast Checker
  • Assistive technology hands-on: VoiceOver testing on the Ground News website
  • PDF remediation: Adobe Acrobat accessibility checker on a scanned document
  • Cognitive accessibility research: a reflection on AI, cognitive load, and machine readability

What I Found

Instagram

In the assignment sample I audited, the university feed had alt text on images, but all of it was auto-generated and inaccurate. A screen reader user gets a description, but the description is wrong. Decorative emoji ran through captions with no aria-hidden treatment, so screen readers announced each one by name. Story text overlays failed contrast requirements. Video content had no captions. The alt text problem alone is fixable with workflow changes. Taken together, the failures suggest accessibility was left to automation.

Contrast Audit

The audit covered three music tech sites: Ableton.com, Fors.fm, and Audiothingies.com. Fors.fm was a surprise. I expected to find violations there and did not. Ableton largely passed. The significant failures were concentrated at Audiothingies.com: gold-colored link text at a 2.4:1 contrast ratio (well below the 4.5:1 WCAG AA minimum under SC 1.4.3), red heading text at 4.3:1 that just misses the threshold, an "Out of Stock" notification and a CTA button that both fail contrast requirements, and small red header text (23px) that does not qualify for the large-text exception.

Failures clustered in specific interactive elements and status indicators instead of spreading evenly across a site. That makes them easy to miss in a casual review, and they matter to users with low vision who depend on those elements.

VoiceOver on Ground News

On Ground News, the focus sequence did not match the visual hierarchy. Interactive elements were unlabeled. Landmark regions were missing, so screen reader users had no efficient way to jump between sections of the page.

PDF Remediation

Starting from a scanned document, I used Adobe Acrobat's accessibility checker to identify reading order failures, missing alt text on figures, and untagged tables. The remediation process required manually setting reading order, writing descriptive alt text, and tagging table structure.

Beyond WCAG: Cognitive Accessibility

WCAG organizes accessibility around four principles: perceivable, operable, understandable, and robust. It does not fully address cognitive load, focus support, or plain language. To fill that gap, I built an evaluation method based on the W3C's COGA (Cognitive and Learning Disabilities Accessibility) task force work and their "Making Content Usable for People with Cognitive and Learning Disabilities" guidance. The goal was to cover users with ADHD, dyslexia, autism, memory impairments, and mental health conditions like communication anxiety.

I developed eight evaluation criteria that sit alongside traditional WCAG checks: plain language, clear iconography, consistent navigation, focus support, memory independence, error prevention, content scannability, and progressive disclosure. I also ran Flesch-Kincaid readability analysis and applied mobile care heuristics for cognitive accessibility. These criteria catch failures that automated tools and contrast checkers do not flag, such as unclear error messages, inconsistent interaction patterns, dark patterns that exploit decision fatigue, and content that demands too much working memory.

Cognitive Accessibility and Machine Readability

Clean semantic structure, descriptive alt text, logical reading order, and properly tagged PDFs can improve human accessibility and machine readability at the same time.

I have been using AI tools to manage cognitive load across a demanding workload, to organize my thinking and reflect on what concepts mean. The experience made me aware of how inaccessible content creates friction for screen reader users and for anyone or anything trying to extract meaning from a poorly structured document or page.

What a Longer Engagement Would Add

A longer engagement would add:

  • Stakeholder interviews before the audit:the team's current workflow, toolchain, and capacity for remediation change what gets prioritized.
  • User testing with assistive technology users: heuristic evaluation and automated checkers do not find everything.
  • Remediation tracking: a prioritized issue log with severity ratings, WCAG criteria references, and remediation owners.
  • VPAT documentation: for enterprise software or any product sold to institutions, a Voluntary Product Accessibility Template is often required.
  • Longitudinal re-audit: accessibility degrades as content is added and codebases change.

VoiceOver / Screen Reader Testing

I tested the Ground News news aggregation website hands-on with the VoiceOver screen reader, navigating the site the way a screen reader user would.

Navigation Patterns Differ From Sighted Browsing

VoiceOver navigation follows a different path than sighted browsing. Focus order, heading hierarchy, and landmark regions become the primary navigation mechanisms. On Ground News, the focus sequence did not match the visual hierarchy, so content was announced in an order that made the page structure unclear. Landmark regions were missing entirely, so there was no efficient way to jump between sections. For a news site, where scanning and quick navigation are core, this is a critical failure.

Dynamic Content Creates Unique Challenges

News sites present challenges that static pages do not: dynamic content updates, embedded advertisements, and multimedia elements all compete for screen reader attention. On Ground News, ads interrupted the reading flow without clear separation from editorial content. Interactive elements lacked accessible labels. Multimedia content had no alternative text or captions.

What Automated Tools Missed

An automated accessibility checker can flag missing alt text or low contrast ratios. It cannot tell you that the reading order makes a page incomprehensible, or that interactive elements are present but unusable.

Instagram Accessibility Audit

I audited a large university Instagram account, examining specific posts for screen reader compatibility, color contrast compliance, and readability.

FIRST Robotics Post: Emoji and Alt Text Failures

The first post examined was a FIRST Robotics team feature. Multiple emojis were used throughout the caption. Screen readers announce each by its Unicode name, which turns visual shorthand into repeated interruptions. The image alt text was autogenerated by Instagram's built-in system. It read text from a shirt in the image without saying what the image depicted or why it mattered. A screen reader user would hear a string of disconnected descriptors instead of understanding that this was a team celebration photo.

Decorative Text Post: Contrast and Readability Failures

The second post used decorative overlay text on an image. The contrast ratio measured at 2:1, which fails the WCAG 4.5:1 minimum for normal text under SC 1.4.3. The text was also set in a cursive font, which creates additional barriers for users with dyslexia or low vision. Decorative type that carries meaningful content and sacrifices legibility is an accessibility violation.

Core Finding: Automated Alt Text Misses Context

Instagram's system can identify what is in an image, but not what the image means in context. It can detect a person, a shirt, a room. It cannot convey that this is a celebration, a team milestone, or a recruiting moment. The fixes: remove decorative emojis from captions, write alt text that communicates purpose instead of inventory, and make text overlays meet contrast minimums.

Accessibility-Aware Requirements

Functional requirements rewritten so accessibility intent is explicit and a Business Analyst could include them in a feature spec without needing engineering input. Each requirement is followed by the bug it would have prevented and the POUR category it supports (POUR is the four WCAG principles above).

Requirement 1: Link destinations

Improved Requirement: Every hyperlink must communicate its destination using its visible text or accessible name alone.

Prevents:links announced as “Read more” without sufficient context.

POUR: Understandable, Operable.

Requirement 2: Form error messages

Improved Requirement: When form validation fails, each invalid field must display a plain-language text error message programmatically associated with that field.

Prevents: error states indicated using red text and icons without additional explanation.

POUR: Perceivable, Understandable.

Requirement 3: Color and status indicators

Improved Requirement: Color or iconography used to communicate state must be paired with a text equivalent that conveys the same information.

Prevents: error states indicated using red text and icons without additional explanation, and status labels announced without contextual meaning.

POUR: Perceivable, Robust.

Requirement 4: Heading hierarchy

Improved Requirement: Every page must use a strict sequential heading hierarchy without skipped levels.

Prevents: heading levels skipped or used inconsistently for structure.

POUR: Understandable, Robust.

Requirement 5: Auto-playing media and reduced motion

Improved Requirement: Video and audio content must not begin playback automatically when the user has enabled the system reduce-motion preference.

Prevents: video content begins playing automatically on page load.

POUR: Operable, Perceivable.

Requirement 6: Focus stability during dynamic updates

Improved Requirement:When content on the page updates dynamically, the user's keyboard focus and reading position must not change.

Prevents: new items injected at the top of a live feed causing keyboard focus to jump.

POUR: Operable, Robust.

Requirement 7: Card interaction boundaries

Improved Requirement: Grouped content that represents a single logical action must function as one keyboard-operable target with one tab stop.

Prevents: cards contain multiple focusable elements creating excessive tab stops.

POUR: Operable, Understandable.

TWO COURSEWORK DOCUMENTS

A navigation specification and a VoiceOver finding on NPR

The first is a specification for this site’s navigation, written for a developer. The second is my accessibility evaluation of two NPR pages, done as independent coursework and not commissioned by NPR.

Navigation specification for nomadjames.comWhat the navigation has to do

I reviewed this site's code as of commit 3aa3768. The specification calls for a labelled main navigation, a named home logo, and aria-current="page" on the active section. At that time the home page had no current-page indicator.

Recommendation: mark the home page as current and build the specified keyboard and focus behavior.

NPR evaluationVoiceOver found a missing state announcement

The report combines axe, WAVE, HeadingsMap, keyboard testing, and VoiceOver on two pages. In VoiceOver, starting or stopping either the persistent home player or the story audio module produced no announced state change.

Recommendation: announce playback state through an aria-live or equivalent status message, then re-test both audio players. The original header lists some checks as scheduled; the keyboard and VoiceOver checks shown here were completed and are documented later in the report.
